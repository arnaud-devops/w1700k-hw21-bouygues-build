# Custom v2.3 Fanboy tools and compatibility policy

Date: 2026-07-25

This source candidate keeps the custom v2.2 Gilly 21.07 network, PPE, Wi-Fi,
DoQ and recovery base, then adds the requested Fanboy general-purpose package
and kernel-module policy. It has not been flashed.

## Added

- `CONFIG_ALL_KMODS`
- pinned buildbot vermagic and matching official Airoha kmods repository
- `owut` and LuCI Attended Sysupgrade
- Dropbear SSH plus `ttyd` and `luci-app-ttyd`
- OpenSSH SFTP plus `luci-app-filemanager`
- CLI APK/recovery plus `luci-app-package-manager`
- browser-side nPerf client and router tools `iperf3`, `curl`, `tcpdump`
- `librespeed-go` and Fanboy's `luci-app-netspeedtest`

The existing `dnsmasq-full` plus dnsproxy DoQ chain, Watchcat policy,
post-sysupgrade DoQ/Wi-Fi recovery, SFTP, health check, pstore, FlowSense,
SQM, MLO panels and network diagnostics remain included.

`bridger` remains excluded because the selected `675-*` nft flowtable bridge
series already owns that acceleration path.

## Forced vermagic

The profile uses:

```text
Linux: 6.18.39
Kernel release: 1
Buildbot vermagic: 7a95fc2977560f4c28e39a71bf89c960
```

The hash and complete kmods URL are stored in the repository. They are not
downloaded dynamically during CI. The build therefore remains reproducible
until a deliberate source commit updates this tuple.

The runtime copy of `/etc/vermagic.txt` is owned by the custom support package
and is not a conffile. It is therefore not intended to migrate as user
configuration into an unrelated future firmware.

`CONFIG_ALL_KMODS` builds the available module packages but does not install
all of them in the firmware. Modules already selected in the image are
compiled against the exact patched kernel.

There is one explicit build exception:

```text
# CONFIG_PACKAGE_kmod-ipt-rtpengine is not set
```

The pinned Telephony feed's RTP Engine module does not compile against Linux
6.18.39 because its source includes a missing `xt_RTPENGINE.h`. It is a SIP
media-proxy module with no role on this router. The feed remains present and
all other eligible kernel modules remain under `ALL_KMODS`; the CI verifies
that this narrow exclusion is still applied.

The forced hash weakens only the post-install boundary: APK can accept an
official OpenWrt `kmod-*` even though the local kernel contains additional
RTL8261CE, Airoha PPE, bridge and MT7996 changes. Package acceptance is not ABI
proof. A module required for permanent operation should still be selected and
rebuilt in this profile.

The matching repository is an OpenWrt snapshot path, not a permanent release
archive. It may disappear when the public snapshot advances. `ALL_KMODS`
compiles the module packages in CI, but this workflow does not publish a
long-lived custom APK feed. The pinned public feed is therefore a convenience,
not a recovery dependency or durability guarantee.

Use APK only for explicit, reviewed package installations. Do not run a bulk
`apk upgrade` from either CLI or LuCI. Kernel modules, base-system components
and packages needed after recovery belong in the next rebuilt firmware image.

## Upgrade tools

`owut` and Attended Sysupgrade are installed but do not run automatically.
The public OpenWrt build service cannot reproduce this repository's UBI2
profile, patchset or support package. An image returned by a generic service
must not be treated as an in-place custom v2.3 update.

The supported custom upgrade path remains the checksum-verified local
sysupgrade procedure. It preserves the recovery hooks and provides an
explicit rollback point.

## Runtime defaults

- `ttyd` is bound to `@lan`, launches `/bin/login` and reuses the LuCI
  uHTTPd certificate and key for TLS.
- no WAN firewall opening is added for `ttyd`, LuCI or LibreSpeed;
- LibreSpeed is installed but disabled by default;
- the Net Speedtest service starts neither its iperf3 server nor LibreSpeed
  until explicitly enabled;
- nPerf is an embedded official web client executed by the administrator's
  browser; it is not an unverified native binary running on the router;
- Net Speedtest status verification is readable, while RPC methods that
  download Ookla CLI or start a test require LuCI write permission;
- Watchcat retains separate conservative `wan` and `wan6` recovery;
- DoQ retains AdGuard Unfiltered primary, NextDNS fallback and DNS.SB
  bootstrap;
- SQM/Cake and MLO remain installed but disabled.

The workflow rejects a build if the pinned vermagic/kmods tuple changes,
`ttyd` is not LAN-bound, LibreSpeed is enabled by default, or any retained DoQ,
Watchcat, Wi-Fi or PPE requirement disappears.
