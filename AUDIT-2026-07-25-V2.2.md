Patch `973` prevents different IPv6 source MAC addresses sharing an Airoha
port from overwriting one fixed UPDMEM slot. It uses locked, referenced slots
per MAC and rejects only an individual flow to software if no slot can be used.

## Checks passed

The seven release assets were downloaded from GitHub and checked independently
with `scripts/audit-w1700k-custom-v2.2-image.sh`. The audit passed:

- OpenWrt checksums, image size, target, board, source and Linux version;
- GitHub build-provenance attestations for every published asset;
- FIT kernel, DTB, rootfs, UBI2 metadata and the 64 KiB ramoops node;
- package manifest and CycloneDX SBOM policy;
- exact builder, container, OpenWrt, Gilly, feed and overlay provenance;
- patches `972` and `973` present, with `971`, `965`, PR 24038 and `bridger`
  absent;
- strict RTL8261CE matching, NPU/MT7996 firmware and mt7996 radar fix;
- full `wpad-openssl`, DoQ and Wi-Fi recovery, dual-stack fw4 and hardware
  offload policy;
- opt-in FlowSense probe, irqbalance, conservative Watchcat, disabled SQM/MLO,
  pstore, SFTP and the intended administration tools.

The macOS `/dev/console` extraction warning is host-only. Linux CI validated
the assembled rootfs, and all regular-file checks completed locally.

## Remaining hardware gate

This proves image structure, provenance and contents, not runtime behavior.
The active router still runs the validated Gilly 17.07 image. A separately
authorized hardware test must cover boot and rollback, RTL8261CE binding,
WAN 10G, multigig LAN2, sustained IPv4/IPv6 PPE traffic, all three APs, DoQ,
Watchcat, pstore and irqbalance before v2.2 can be recommended as stable.
